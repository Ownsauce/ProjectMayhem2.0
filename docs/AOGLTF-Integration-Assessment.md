# AOGLTF Integration Assessment

## Useful capabilities

- Reads an AO installation through an `RdbController` backed by the bundled
  `AODB.dll` and `AODB.Common.dll`.
- Exports ABIFF meshes and CIR character meshes by individual resource ID.
- Exports a playfield by ID into separate terrain, statel, collision, and water
  outputs.
- Supports GLB and glTF output and configurable axis mirroring.
- Terrain GLB output can embed its generated texture atlas.

The internal API has appropriate request granularity for Project Mayhem. Broad
pre-export is not inherently required.

## Integration blockers

- The executable ignores command-line arguments and opens an interactive
  console menu. It cannot currently serve as an unattended runtime converter.
- The project targets `.NET 8` with `PlatformTarget` set to `x86`, which is a
  poor fit for a cross-platform 64-bit Unity client.
- Critical database parsing is supplied as binary-only `AODB.dll` and
  `AODB.Common.dll`; the playfield-capable source was not found in the linked
  repository search.
- The AOGLTF repository contains no license file or other grant permitting its
  code or bundled DLLs to be redistributed or incorporated.
- Export methods frequently collapse exceptions into `false`, limiting useful
  runtime diagnostics.

## Decision

Project Mayhem
bundles the required `AODB.dll` and `AODB.Common.dll` Unity runtime assemblies.
for AOGLTF itself. Keep `IAOAssetConverter` independent.

AOGLTF becomes a strong first converter if its author provides:

1. a license or explicit permission covering the AOGLTF source;
2. a non-interactive CLI such as
   `aogltf export-playfield --ao <path> --id <id> --output <dir> --format glb`;
3. meaningful exit codes and error output;
4. a supported Linux/x64 build, or confirmation that Project Mayhem may ship a
   separately launched platform build.

If those are unavailable, implement a clean Project Mayhem resource reader and
use AOGLTF outputs only as behavioral test references generated by developers.
